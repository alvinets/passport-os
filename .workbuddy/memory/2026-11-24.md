- TLS 全面失败的根因（与"第一个固件能用"并不矛盾，是两件事）：
  1) ESP32-C3 `CONFIG_MBEDTLS_HARDWARE_MPI` 只支持 ≤3072 bit（SOC_RSA_MAX_BIT_LEN=3072）。证书链里出现 RSA-4096（Let's Encrypt `ISRG Root X1` 签的 R10/R11 中间证书、sig_len=512）时，PSA 验签路径不会走 `MBEDTLS_LARGE_KEY_SOFTWARE_MPI` 的软件回退，直接返回 `PSA_ERROR_INVALID_SIGNATURE (-149)`。日志特征：`esp-x509-crt-bundle: Key type: 0x4001 ... sig_len=512` → `PSA signature verification failed 0xffffff6b (-149)`。
     实测：`# CONFIG_MBEDTLS_HARDWARE_MPI is not set` 后 air-quality(api.open-meteo.com 子域) 立刻 `Certificate validated` + 拉到 PM2.5；此前同一请求必失败。
  2) `components/mbedtls/esp_crt_bundle/cacrt_all.pem` 只有 145 张 CA，**缺 2026 版 Let's Encrypt 新根 `ISRG Root YR`**（有 `ISRG Root X1`）。`esp_crt_find_cert()` 用 `memcmp(issuer, subject, MIN(len))` 做**前缀匹配**，于是 "Root YR" 被误配到 "ISRG Root X1"，报"Certificate matched with ISRG Root X1 but signature verification failed"——把"根证书缺失"伪装成"验签失败"。天气域名 api.open-meteo.com 正好是这条链，所以天气仍失败；air-quality 子域是另一条链所以能过。
